# Brano v1.8 Home Widget Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A 4x1 home screen widget (cover, title, artist, previous/play-pause/next) that the playback service updates only on change and whose buttons work with the app closed.

**Architecture:** Classic `AppWidgetProvider` + `RemoteViews`, no new libraries. The playback service pushes a small `WidgetState` through `WidgetUpdater`, which skips duplicates, does nothing when no widget is placed, and persists the last state so the provider can redraw after a reboot. Buttons send media-button key events through Media3's `MediaButtonReceiver`; a cold start is handled by `MediaSession.Callback.onPlaybackResumption`.

**Tech Stack:** Kotlin, Media3 1.8 (session), Coil 2.7, Hilt, JUnit4 + Truth + Robolectric 4.16 + mockk.

**Spec:** `docs/superpowers/specs/2026-11-10-widget-design.md`

## Global Constraints

- No new dependencies (no Glance). Guava `SettableFuture` is already on the classpath through Media3.
- No periodic updates: `updatePeriodMillis="0"`.
- Widget: `targetCellWidth=4`, `targetCellHeight=1`, `resizeMode="horizontal"`, label "Brano · Barra".
- Cover 48dp, corners 10% (as `CoverShape`); thumbnail bitmap 144x144 px, `allowHardware(false)`.
- Background = `playerColors(seed).deep`; fallback `#14101F`. Text white, artist at 70% alpha.
- Corner radius: `@android:dimen/system_app_widget_background_radius` on API 31+, 16dp below.
- Empty state copy: title "Brano", subtitle "Tocca ▶ per iniziare".
- Widget errors are logged and never stop playback.
- Version 1.8, versionCode 8; LRCLIB User-Agent "Brano/1.8 (Android music player)".
- Gradle via PowerShell: `$env:JAVA_HOME='C:\Program Files\Android\Android Studio\jbr'; .\gradlew.bat ...`.

## Review Focus

1. Play pressed while the service is cold and `restoreQueue` has not finished: must still resume the saved queue (Task 4, resumption waits for the restore job).
2. Resumption with shuffle on: the restored shuffled order and `unshuffledIds` must survive the session's `setMediaItems` (Task 4, `keepOrderOnce` test).
3. Track with no album art or an unreadable one: widget shows the note icon, never a blank tile (Task 3 test, artwork returns null).
4. Many quick state changes (skipping fast): only the latest cover is pushed; an older artwork load must not overwrite a newer track (Task 3 test, latest wins).
5. Saved queue whose files were all deleted: resumption returns an empty list, widget falls back to the empty state (Task 4, emulator step).
