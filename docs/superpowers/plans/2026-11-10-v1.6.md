# Brano v1.6 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (chosen: Native). Steps use checkbox (`- [ ]`) syntax.

**Goal:** music-folder selection, hide/delete tracks, synced lyrics (local, embedded, optional LRCLIB).

**Architecture:**
- Room v2 replaces `excluded_folders` with `music_folders` and `hidden_tracks`; `LibraryFilter` applies both.
- Lyrics live in `app.brano.lyrics`: pure parsers, a source chain in `LyricsRepository`, and a player view toggled in place of the disc.

**Tech:** Kotlin, Compose M3, Room 2.8, Media3, DataStore, kotlinx.serialization, HttpURLConnection, JUnit4/Truth/Robolectric/mockk.

**Spec:** `docs/superpowers/specs/2026-11-10-v1.6-folders-hide-lyrics-design.md`

## Global Constraints

- No new libraries.
- Network only for LRCLIB, and only when `AppSettings.onlineLyrics` is true. User-Agent `Brano/1.6 (Android music player)`, timeout 8 s.
- Lyrics are loaded only while the lyrics view is shown, on `Dispatchers.IO`.
- Delete:
  - API 30+ uses `MediaStore.createTrashRequest(..., true)`;
  - API 29 uses `delete` plus `RecoverableSecurityException`;
  - API 26–28 hides the action.
- **Environment:**
  - Git Bash needs `export JAVA_HOME="/c/Program Files/Android/Android Studio/jbr"`;
  - tests run with `./gradlew :app:testDebugUnitTest`;
  - the full check is `./gradlew :app:testDebugUnitTest :app:assembleRelease :app:lintDebug`.

## Review Focus

1. **Music folders on an SD card** (`XXXX-XXXX:Music`) map to `/storage/XXXX-XXXX/Music`. An unmappable tree is rejected with a message. Pinned in Task 2.
2. **A folder that is a prefix of another** (`/Music` and `/Music2`) must not match. Pinned in Task 1.
3. **LRC with several time tags on one line, or an `[offset:]`.** Pinned in Task 4.
4. **Embedded USLT in UTF-16 with a BOM.** Pinned in Task 4.
5. **Deleting the track that is playing** removes it from the queue, and playback moves on. Pinned in Task 3 (queue helper test).

### Task 4: Lyrics core

**Files:** new package `app.brano.lyrics`:
- `Lyrics.kt`
- `LyricsParser.kt`
- `EmbeddedLyrics.kt`
- `LrclibClient.kt`
- `LyricsRepository.kt`
- a DI binding in `di/LibraryModule.kt` or a new `di/LyricsModule.kt`
- tests for each

**Interfaces:**
- `enum LyricsSource { CACHE, FILE, EMBEDDED, ONLINE }`
- `data class LyricLine(val timeMs: Long?, val text: String)`
- `data class Lyrics(val lines: List<LyricLine>, val synced: Boolean, val source: LyricsSource)`
- `object LyricsParser`:
  - `parse(text: String, source): Lyrics?`, which is null for blank text. Lines are sorted by time when synced, and the offset is applied as `time - offset`, the LRC convention: a positive offset means the lyrics come earlier.
  - `currentLine(lines, positionMs): Int`
- `object EmbeddedLyrics`:
  - `fromId3(bytes: ByteArray): String?`: ID3v2.3/2.4, frames `SYLT` (rebuilt as LRC text) then `USLT`. Encodings 0 (Latin-1), 1 (UTF-16 with BOM), 2 (UTF-16BE), 3 (UTF-8). Handles synchsafe sizes in v2.4.
  - `fromFlac(bytes: ByteArray): String?`: reads the `VORBIS_COMMENT` block, keys `LYRICS` then `UNSYNCEDLYRICS`, case-insensitive.
  - `read(stream: InputStream): String?`: sniffs `ID3` or `fLaC` and reads at most 1 MB.
- `class LrclibClient(fetch: (URL) -> Pair<Int, String>?)`:
  - `buildUrl(track): URL`, with `track_name`, `artist_name`, `album_name` (when present) and `duration` in seconds;
  - `suspend find(track): Result`, where `Result` is `Found(text)`, `NotFound` or `Failed`;
  - reads JSON `syncedLyrics` and `plainLyrics` with kotlinx.serialization (`ignoreUnknownKeys`).
- `class LyricsRepository(cacheDir: File, sidecar: suspend (Track) -> String?, embedded: suspend (Track) -> String?, online: LrclibClient, onlineEnabled: () -> Boolean, now: () -> Long)`:
  - `suspend load(track): Lyrics?` tries, in order: the cache `"<id>.lrc"`, the sidecar, the embedded text, then online (if enabled and no `"<id>.miss"` file younger than 7 days);
  - online writes the cache on `Found` and the `.miss` file on `NotFound`.
- **Production lambdas:**
  - **sidecar:** finds the music folder containing `track.folder` among the DAO entries, walks down with `DocumentFile.fromTreeUri` to the file `<name>.lrc`, and reads it;
  - **embedded:** `contentResolver.openInputStream(track.contentUri)`.
